Weekly threat briefing // 2026-11-25

AI agents speed up real attacks

TL;DR

  • Attackers are using AI agents to go from a new flaw to full access in minutes ( Dark Reading).
  • Three AI hosting providers lost customer prompts for months, and LiteLLM servers are under attack ( The Hacker News).
  • New MCP and agent-platform CVEs show local tools that web pages or attackers can still reach ( CVE-2026-136630).

The week in agent security

The new fact this week is speed. Reports describe attackers using AI pentesting tools against real targets, not only in labs. The FBI warned about an open-source framework called ARTEX ( Aikido Security). Another report says a China-linked group used a similar tool against universities ( Dark Reading). In India, CERT-In (the national response team) reports AI-assisted attacks that caused unauthorized bank payments ( The Hacker News).

The second theme is trust in the layer below your agent. Model routers, hosting providers and gateways see your prompts and keys. When one fails, every customer is exposed. A review of 50 incidents this year reaches the same view: most came from exposed secrets, wide access and weak isolation ( Aikido Security).

The third theme is old bugs in agent tools. MCP (Model Context Protocol, the tool link for agents) servers keep shipping with weak origin checks and file path checks ( CVE-2026-136620). Agent platforms also leave code sandboxes running after use ( CVE-2026-132260).

Some commentary says AI creates "vulnerability hysteria" ( Dark Reading). In our view, the panic is partly fair and partly noise. The speed is real. Most successful attacks still use basic mistakes.

Top stories

Attackers using AI

Cairn and ARTEX: AI pentest tools used in attacks

Dark Reading reports that a China-nexus actor used the Cairn penetration testing tool against East Asian universities. The actor exploited a zero-day in a medical imaging app and reached root in about 11 minutes ( Dark Reading). CISA added the MONAI Label flaw to its Known Exploited Vulnerabilities (KEV) list, and the headline says AI agents exploited it ( The Hacker News). Separately, the FBI warned about ARTEX, and Aikido gives defender advice ( Aikido Security).

This matters because patch windows are shrinking. Agents also try many paths without getting tired. We cannot tell from the excerpts how much work humans did.

Threat level: Critical. Active exploitation is reported, and CISA lists one flaw.

Model infrastructure

OpenRouter drops three providers after prompt theft

Researchers at Dragos say attackers stole data from inside three AI inference providers for months. None of the three knew until they were told. Some stolen requests were marked Zero Data Retention ( The Hacker News). OpenRouter removed the providers after finding they broke their data-handling rules and exposed sensitive data ( BleepingComputer).

If your agents send code, keys or customer data through a router, the weakest provider sets your risk. A "zero retention" label is a promise, not a control.

Threat level: High. Real data theft is reported, but we do not know what each customer lost.

LiteLLM guardrail escape and active scanning

A write-up lists CVE-2026-40217, a LiteLLM guardrail sandbox escape, in the CISA KEV list ( Rescana). Another report says attackers scan LiteLLM servers for critical flaws that allow remote code execution (RCE) ( CyberSecurityNews). Both are discovery leads from news sites, so check the CVE record and the vendor advisory yourself. LiteLLM gateways often hold keys for many model providers, so one bad server can expose many accounts.

Threat level: Critical. KEV listing means exploitation, but confirm the details first.

Tool security

Electerm MCP widget open to DNS rebinding

CVE-2026-136630 affects Electerm before 5.9.0. The MCP Server widget does not validate origins properly, so a web page can use DNS rebinding (a trick that points a site name at 127.0.0.1) to call it and run commands ( CVE-2026-136630). A user only needs to visit a bad page. The excerpt is cut off, so confirm the full impact in the advisory.

Threat level: High. Details are public and the product is real. No exploitation is reported.

pain001-mcp path traversal and AutoGPT sandboxes

CVE-2026-136620 affects pain001-mcp 0.0.72 before 0.0.80. An attacker can write files outside the output folder by using a self-issued confirmation token ( CVE-2026-136620). For a payments tool, that is a serious risk. CVE-2026-132260 says AutoGPT's E2B code blocks, including a Claude Code block, can leave sandboxes running before 0.11.0 ( CVE-2026-132260).

Threat level: Medium. The flaws are credible, but the reach is narrower.

Expert take: threats and trends

Attackers are changing speed, not method. They use AI to find and chain known weak points faster. Tool names such as ARTEX and Cairn will get headlines, but the defence is the same: patch quickly, limit access and watch for odd behaviour.

Too much attention goes to jailbreak papers. A new preprint shows suffix attacks can be sampled more cheaply ( arXiv AI-security papers). Another essay argues that a weaker filter cannot safely vet input for a stronger model ( Check Point Research). These are useful ideas, but we see more damage from leaked keys and open services. Preprints are unreviewed.

Worth watching: attestation for agents. One preprint proposes proving agent identity in HPC (high-performance computing) clusters, to stop a hijacked but authorized agent ( arXiv AI-security papers). Also watch fraud, where a preprint tests whether hosted models will run a scam seller role ( arXiv AI-security papers), and a talk on token fraud covers abuse of paid model access ( Simon Willison).

Compared with last week, MCP bugs stayed the same and provider trust got worse. Last week a vendor key leak hurt one tool. This week, theft inside hosting providers hit many customers.

Watch next week: KEV updates for LiteLLM, ARTEX follow-ups and new MCP origin-check CVEs.

Defender checklist

  • Patch Electerm to 5.9.0 or later, and block untrusted web pages from reaching local MCP ports ( CVE-2026-136630).
  • Upgrade pain001-mcp to 0.0.80 or later, and remove self-issued confirmation tokens from approval flows ( CVE-2026-136620).
  • Upgrade AutoGPT to 0.11.0 or later, and list any E2B sandboxes still running ( CVE-2026-132260).
  • Check LiteLLM versions against the vendor advisory and KEV entry, and rotate stored provider keys if exposed ( Rescana).
  • Review which AI providers see your prompts, and treat zero retention claims as unverified ( The Hacker News).
  • Shorten your patch time for KEV items, because exploit tools now move in minutes ( Dark Reading).

Detection ideas

  • Add a scanner rule for MCP servers that bind to 0.0.0.0 or skip Host and Origin checks, motivated by DNS rebinding ( CVE-2026-136630).
  • Add a rule for MCP tools that take file paths without limiting them to an output folder, mapped to path traversal ( CVE-2026-136620).
  • Add a sample that flags agent configs sending prompts to unvetted inference providers, mapped to OWASP LLM sensitive information disclosure ( The Hacker News).
